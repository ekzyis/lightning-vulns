# lightning-vulns

A list of lightning CVEs (Common Vulnerabilities and Exposures).

| CVE ID | Description | Patched | CVSSv3 | References |
| --- | --- | --- | --- | --- |
| [**CVE-2019-12998**](https://nvd.nist.gov/vuln/detail/CVE-2019-12998), [**CVE-2019-12999**](https://nvd.nist.gov/vuln/detail/CVE-2019-12999), [**CVE-2019-13000**](https://nvd.nist.gov/vuln/detail/CVE-2019-13000) | A lightning node accepting a channel must check that the funding transaction output does indeed open the channel proposed. Otherwise an attacker can claim to open a channel but either not pay to the peer, or not pay the full amount. Once that transaction reaches the minimum depth, it can spend funds from the channel. The victim will only notice when it tries to close the channel and none of the commitment or mutual close transactions it has are valid. | c-lightning v0.7.1, lnd v0.7.1, eclair v0.3.1 | 7.5 | [lightning-dev](https://lists.linuxfoundation.org/pipermail/lightning-dev/2019-September/002174.html) |
| [**CVE-2021-41591**](https://nvd.nist.gov/vuln/detail/CVE-2021-41591), [**CVE-2021-41592**](https://nvd.nist.gov/vuln/detail/CVE-2021-41592), [**CVE-2021-41593**](https://nvd.nist.gov/vuln/detail/CVE-2021-41593) | The current BOLT specification only requires Alice's `dust_limit_satoshis`(applied on Alice's commitment) to be under Alice's `channel_reserve_satoshis` (applied on Bob). As those 2 parameters are selectable by Alice, she can inflate the dust limit until reaching the implementation-defined max value (e.g LND: 20% of chan capacity, LDK: 100% of chan capacity). | eclair v0.6.2, lnd v0.13.3, ldk v0.0.102 | 9.4 | [lightning-dev](https://diyhpl.us/~bryan/irc/bitcoin/bitcoin-dev/linuxfoundation-pipermail/lightning-dev/2021-October/003257.txt)
| [**CVE-2022-39389**](https://nvd.nist.gov/vuln/detail/CVE-2022-39389) | All lnd nodes before version v0.15.4 are vulnerable to a block parsing bug that can cause a node to enter a degraded state once encountered. In this degraded state, nodes can continue to make payments and forward HTLCs, and close out channels. Opening channels is prohibited, and also on chain transaction events will be undetected. This can cause loss of funds if a CSV expiry is researched during a breach attempt or a CLTV delta expires forgetting the funds in the HTLC. | lnd v0.23.3, lnd v0.15.4-beta | 8.1 | [lnd/issues/7096](https://github.com/lightningnetwork/lnd/issues/7096), [lnd/pull/7098](https://github.com/lightningnetwork/lnd/pull/7098), [GHSA-hc82-w9v8-83pr](https://github.com/lightningnetwork/lnd/security/advisories/GHSA-hc82-w9v8-83pr) |
| [**CVE-2024-38359**](https://nvd.nist.gov/vuln/detail/CVE-2024-38359) | A parsing vulnerability in lnd's onion processing logic led to a DoS vector due to excessive memory allocation. | lnd 0.17.0-beta | 7.5 | [GHSA-9gxx-58q6-42p7](https://github.com/lightningnetwork/lnd/security/advisories/GHSA-9gxx-58q6-42p7), [Delving Bitcoin](https://delvingbitcoin.org/t/dos-disclosure-lnd-onion-bomb/979), [Matt Morehouse](https://morehouse.github.io/lightning/lnd-onion-bomb/) |
